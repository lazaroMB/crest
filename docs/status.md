# Project status

Where crest is going next: [vision and roadmap](vision.md).

crest is a **work in progress**. Every phase of the original plan is implemented, `make check` passes, and CI runs on Ubuntu 24.04, macOS 15 and Windows (clippy and tests) on every push; releases (Linux x86_64, macOS arm64 and x86_64, Windows x86_64) are built by `release.yml` on each `v*` tag. Before relying on crest for real work, keep in mind what has not been tested and what is still missing.

## Unverified

- It has not been tested against the real Anthropic API in the development environment: every test uses scripted models or `wiremock`, and `make test-live` has not been run here. The default model ids (`claude-sonnet-5-5`, `claude-opus-5-5`, `claude-haiku-5-5`, `claude-fable-5-1`) are validated against `GET /v1/models` at startup.
- macOS has not been tested on a real machine: CI builds and tests there, but nobody has used the window on a Mac.
- Windows has only been built and tested in CI: nobody has used the window on a Windows machine. Tests that need symlinks or POSIX tools run on Unix only. On Windows a command's child processes are killed with `taskkill /T` while the command is alive; children left behind after it exits are not (Unix kills its whole process group).
- The decision model (Cloudflare Clef) has only been tested against a mock server, not with a real token.
- The installer (`scripts/install.sh`) is tested on a temporary prefix with a fake binary on Linux and macOS (CI), but `crest.app` has not been opened on a real Mac. Signing (Developer ID + notarization; SignPath on Windows), the Homebrew tap and winget are wired in `release.yml` but have not run yet: they need the repository secrets. Windows stays unsigned until SignPath accepts the project (it asks for proof of reputation), so a setup downloaded with a browser gets a SmartScreen warning; winget and `install.ps1` do not. crest.app now re-executes itself through the login shell (`platform::login_shell`) instead of a launcher script; not tried on a Mac.
- Reading the API key or plugin secrets from the system keyring has not been tested (the tests use the environment fallback).
- The rtk integration (`app.opt.rtk`) has only been tested with a fake `rtk` script that follows the `rtk rewrite` exit-code contract, not with the real binary.
- The chat blocks for technical work (statistics, calc and solver cards, recompute, number slots, LaTeX math, forms, plots, reports, the developer, engineering and science viewers, the shared widgets, cards from other formats, copy-as) are covered by unit and `#[gpui::test]` tests only: the window has not been opened to look at them, so layout, colours and focus behaviour are unchecked. Phase 2 was built piece by piece with each crate's targeted tests and clippy; the whole `make check` has not been run on it yet. The statistics engine is checked against NIST StRD and R reference values, the new cards against textbook and closed-form values (power, contingency, bootstrap with a seed, known LPs, beams, NPV/IRR); the Python and R reproduce lines have not been run against those tools.
- Most viewer fixtures are generated or hand-written. STEP was tried on 31 public files (truck samples, CAx-IF AP214, KiCad and FreeCAD models): files from FreeCAD, KiCad, OCCT and Onshape mesh completely, some CATIA sub-parts fail to mesh (reported as faces not meshed) and one file does not tokenize. Waveforms were tried on VCD only (no FST or GHW sample), and the PubChem lookup only against saved responses.
- The privacy layer works by patterns: it catches well-known key formats and validated personal data, not every secret (a password with only letters, a custom token format). Add `app.opt.privacy.patterns` for your own formats.

## Behavior to keep in mind

- `Ctrl+C` stops a running workflow step in the window; the workflow stays saved at its last checkpoint and `/research resume` or `/implement resume` runs the step again. In headless mode it kills the process (the same resume applies).
- At workflow gates, an empty line counts as an approval (`yes` / `continue`). In the implementation workflow that can commit with failing criteria or close the workflow.
- In the implementation workflow, only `edit_file` and `write_file` are restricted to the task's files: `run_command` can touch others (although the commit only includes the task's files).
- crest ships no model prices: until you set `app.opt.pricing`, the cost segment shows the session's tokens (`48.2k tok`) instead. The cost lives in memory, so a resumed session starts again at `$0.00` against the cap.

## Not available yet

- The font is not configurable (JetBrains Mono when installed).
- `app.opt.leader` only affects mappings defined in Lua; the builtin ones always use `Ctrl+G`. Actions such as `session.resume` are not implemented.
- There is no command to list or pick older sessions: the workspace's last one is always resumed.
- Compaction assumes a 200,000-token context window, whatever the model, and its threshold is not configurable.
- `/mcp trust` takes effect the next time you open crest; `--trust-mcp` starts the server in the same run. (`/plugin trust`, by contrast, takes effect at once.)
- Plugin capabilities cover HTTP(S) to listed hosts and listed programs; there is no file-system capability, and a slow `app.http` or `app.shell.run` call holds the Lua VM (other hooks wait) until it finishes or times out.
- Simulation (MVP): flat state machines, FIFO queues and timers as self-messages; no latency percentiles, load generators, fault toggles in the board, GIF/video export or re-simulation inside `board.html` yet, and the board has only a dark theme. See [docs/research/solution-simulator.md](research/solution-simulator.md).
- Modals draw images, documents, tables, diagrams and 3D models (OBJ, STL, PLY, geometry only) natively, but cannot embed web pages (links open the browser), PDFs or a terminal yet; images larger than the GPU's texture limit (often 8192 or 16384 px) fail to draw. See [docs/research/rich-content-modals.md](research/rich-content-modals.md) for the roadmap.
- Chat blocks, known gaps after phase 2 (details in the [research note](research/chat-blocks-for-technical-work.md#roadmap)):
  - There is no Python/R bridge, so no GLM, SymPy-checked derivations or SARIMAX cards. The power and decision cards have no editable inputs. LP ranging is not reported. Only `stats_test` counts towards the multiple-testing warning, and the count resets when crest restarts.
  - Developer viewers: no differential flame graphs and no perf-script or speedscope input; the log histogram does not filter on click, and only the first 16 MiB of a log are read; the trace's critical path is a row filter; only PostgreSQL JSON plans (no text `EXPLAIN`, no MySQL/SQLite/DuckDB); DOT shapes and literal colours are not drawn, and ER columns are listed beside the boxes, not in them; pasted plans and HARs are not detected on their own.
  - Engineering: no assembly placements, face picking, mass properties or section cap for STEP; DXF text is drawn unrotated, hatches, dimensions and images are only counted, and `/open` does not show DXF; IFC has no 3D view or storey plan and no zones; SPICE subcircuits are not flattened and `.include` is not followed; beams have no hinges, springs, axial loads or varying E·I; Bode has no root locus and no closed-loop poles with a dead time; no material database and no BOM price breaks.
  - Sciences: chemistry and science envelopes have no Recompute; sequences show forward frames only, with no MW/pI, no linear map and 50 bundled enzymes; spectra read no 2D NMR, have no integration or overlays and show one MS scan; GHS precautionary statements are codes only and the pictograms are not the official symbols; maps have no base map tiles and no WKT CRS (EPSG codes from a bundled list or PROJ strings); array files are read whole (512 MiB at most) and NetCDF-4 dimension names are not read; networks have no Louvain or GraphML and unweighted betweenness and closeness; Gantt charts have no holidays, resource levelling or dependency arrows; training curves read no TensorBoard event files.
  - Interop: card inputs are drawn as fields below the card, not in place; A2UI function calls, checks other than `required` and live Modal/Tabs are not implemented, and only the basic catalog is drawn; Adaptive Cards templating, `selectAction`, live `Action.ToggleVisibility`, `inlineAction` and `refresh`/`authentication` are not supported; Vega-Lite beyond a simple single view is shown as JSON; MCP Apps HTML views are not run, and `/mcp` does not list the app-only tools it hides.
  - Left from phase 1: no Arrow IPC datasets, no stereo wedges on molecules, a fixed grid for implicit curves, copy-as only on the selected block.
- Langfuse export requires building with `--features langfuse`; the `make release` binaries do not include it.
- No native installers on macOS and Linux (.dmg, .deb, AppImage) and no in-app updates: `brew upgrade`, `winget upgrade` or the install script again. See [docs/research/installation.md](research/installation.md).
